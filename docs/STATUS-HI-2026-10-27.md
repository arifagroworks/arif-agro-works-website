## Supabase की read-only जाँच

- सभी 20 public tables पर RLS enabled है। Policy/function/constraint/trigger definitions पढ़ी गईं; business records का export या modification नहीं किया गया।
- Salary guard worker row को lock करके available balance जाँचता है; overpayment रोकने का isolated test पास है। Final Food settlement और Invoice payment guards भी मौजूद हैं।
- Local schema-derived tests में disabled Incharge का Production access और cross-site Food worker mismatch पुराने definitions पर reproduce हुए। उनके fixes proposal में हैं।
- Billing tables के Master-only access और assigned-site worker visibility के isolated tests पास हैं।
- Security advisor में trigger-only functions की public EXECUTE permissions, signed-in definer-function permissions और leaked-password protection warning मिली। प्रत्येक SECURITY DEFINER warning को खुद में exploit का प्रमाण नहीं माना गया।
- Performance advisor में 13 missing foreign-key covering indexes के findings सहित अन्य performance warnings मिले। इन्हें बिना query workload जाँचे production में नहीं बदला गया।

## Backend fix package: तैयार, production में लागू नहीं

`database/proposals/access-hardening.sql` local isolated PostgreSQL tests में पास है। इसमें:

1. Disabled Master/Incharge का access, Production access और privileged Food/Payment RPC gates कड़े करना।
2. Food की पुरानी permissive policies हटाकर worker का वही site होना enforce करना।
3. Trigger-only functions से unnecessary public execution grants हटाना।
4. Food allocation में exact paise distribution और whitespace वाले manual FOOD advances से duplicate deduction रोकना।

यह production migration नहीं है और अपने-आप deploy नहीं होता। Production पर इसे लागू करने के लिए पहले आपकी स्पष्ट database-change अनुमति चाहिए, क्योंकि पहले production database न बदलने की शर्त थी। Local tests grants/defaults के simplified fixture पर हैं; यह live Auth service, JWT refresh, concurrency load या device end-to-end certification नहीं है।
